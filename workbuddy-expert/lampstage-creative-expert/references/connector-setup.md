# WorkBuddy Connector setup

The Expert declares one streamable HTTP MCP dependency named `lampstage` with:

- MCP URL: `https://lampstage.com/api/mcp`
- Authentication: `Authorization: Bearer <LAMPSTAGE_API_KEY>`
- Discovery tools: `health` and `capabilities`
- Version 0.8 image path: reuse selected assets or `POST /assets` → check live `image.generate` ordered-reference schema/limits/models → one `POST /image-jobs` → save `job_id` → `GET /jobs/:id` → inspect outputs. New MCP calls use one asset OR 1–6 ordered references plus prompt and explicit 1–4 output count; both models have an application cap of6 and only `1_1` ratio is advertised. Four/six-reference OpenLux generation has not been live verified. See the [image workflow](../skills/image-generation/references/multi-reference-images.md). This creation starts paid work; an unknown result must not trigger automatic resubmission or video-list recovery.
- Video path: plan/edit/check locally → explicit user submission → upload source and selected images → check `video.replicate` with `modes.six_references` and `status: available` → create once with explicit mode, 1–6 ordered references and semantic `segment_plan` → save/reuse job ID → prepare → review snapshots, windows and quote → render ready segments with review token and authorized budget → play candidates → review exact candidate hashes → assemble accepted segments → play final output
- Lifecycle v1: `get_account_usage` → `GET /account/usage`; `list_video_jobs` → `GET /video-jobs`; `cancel_video_job` → `POST /video-jobs/:id/cancel`. Check `video.replicate.lifecycle.version: 1` (or the live remote server's three tools). A local bridge's advertised tool list does not prove its target server has upgraded.
- Version 0.6 delivery/templates: check live `video.delivery` and `video.templates` with `status: available`; `get_video_delivery`, `submit_video_feedback`, `list_video_templates`, `get_video_template`, `update_video_template`, and optional `create_video_job.template_version_id` follow the [MCP contract](mcp-contract.md). Only the user's explicit “satisfied and save template” choice permits saving. Reuse starts a fresh reviewed task, not an old receipt or accepted candidate.
- Video observation: bounded 30–60-second read-only checks; stop waiting when review is needed, retain full action/audio checks, and provide full output plus all segments. Refresh expired URLs by reading the same job/delivery, never by editing signed query parameters.
- Version 0.7 characters: check live `characters.library`; use `list_characters`, `get_character`, `save_character`, `save_character_version`, `update_character`, and `list_character_assets` as specified in the [MCP contract](mcp-contract.md). The remote catalog totals26, stdio27 including local upload. Saving explicitly selected character references does not require a satisfactory film or save a T-code template. Keep fixed version/image indices and a stable save idempotency key; inspect ambiguous results before retry. Existing image uploads may share exact bytes through backend deduplication, but do not claim original image URLs are private.
- Request timeout: at least 90 seconds for asynchronous job creation

Keep `LAMPSTAGE_API_KEY` in the WorkBuddy native credential dialog or connector secret field. Each user creates a personal key at `https://lampstage.com/account`; shared keys merge credits and task history. Never ask for or paste any API key, token or password into chat. On 401, update the native secret outside chat and verify with an authenticated read-only management request when supported, not health/capabilities or a test job. The existing token declaration is retained; do not invent another credential schema or silently change host configuration. The checked-in `scripts/lampstage-http.mjs` bridge remains available for local validation. Ecommerce keyword optimization runs in the Expert from confirmed facts. Six-reference preparation uses uploaded images; it does not create state images.
The bundled stdio bridge additionally offers `upload_local_asset` for an exact absolute user-supplied file path. It validates the file locally and sends multipart using the configured API key. The remote MCP server has no access to client files, so its upload path remains public `http(s)` URLs. Older jobs keep their recorded route.

The video management workflow keeps unfinished edits in the local task workspace outside this package. A structural video 429 stops automatic creation: inspect account usage and existing video jobs, continue a chosen task or cancel only a selected safe draft. Independent draft/active limits default to 10 each; cancelling a draft cannot release active capacity. Eligible drafts expire 24 hours after creation without media deletion. Save the returned job ID and recover uncertain video responses with list/get, never blind retries or switching keys. Image recovery follows its separate rule above. This release does not implement remote draft editing or create-idempotency support. Reimport the new package to update client guidance/bridge; the remote server and an existing installation do not update merely because source files changed.
