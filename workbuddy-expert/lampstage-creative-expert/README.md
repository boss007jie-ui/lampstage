# Lampstage Creative Expert · 0.10.1

0.10.1 在既有首次分析中明确核对停顿、定格与结尾停留是否同全局指令、逐段动作及 `after_state` 一致，并在既有候选播放中检查停顿是否出现在计划时点、结尾停留前是否完成要求的动作。保留合法停顿，禁止用静图替代必需动作；不增加正常调用、轮询、生成或人工确认轮次。只核对实际取得的提示词，不把不可见的上游最终提示词记为已核验。详见[生产检查](skills/video-generation/references/production-workflow.md)。

Version 0.10.0 requires a reviewed, complete-scene `start_state` in the first reference slot of every new six-reference segment. The Expert checks source action and camera changes against that image during the existing first analysis, then reads deterministic `candidate_timing` from the current job before candidate decisions. The local bridge retains allowlisted review failure reasons and safe timing fields. Official assembly may hold the final frame for at most one 30 fps frame (1/30 second) for frame quantization; explicit reviewed trim and the 15% retime limit remain in force. Timing compatibility alone does not establish visual quality, and no automatic trim or paid retry is introduced.

Version 0.9.0 added explicit closure of stopped review/attention video jobs. Select the exact job, confirm the user has abandoned it, read `can_close` and its revision, then call `close_video_job`; never close work automatically to bypass quota. A closed job cannot continue.

This WorkBuddy Expert combines product understanding, ecommerce copy, image generation, reference-video replication, and job/asset handling through the Lampstage API.

Version 0.8.0 adds [ordered multi-reference image creation](skills/image-generation/references/multi-reference-images.md). Supply 1–6 separate character/product/scene/state images, optionally with fixed character bindings, and request 1–4 outputs independently. A mother, baby, product and scene can create one complete scene without a pre-composed collage. Model choice is explicit; both current models have an application reference cap of 6 and advertise only square `1_1` output. The bridge schema and required fields match remote MCP. Single-asset input remains supported with explicit prompt and output count. Inputs are checked before submission; an unknown image-create outcome never triggers an automatic repeat or video-list recovery.

Four/six-reference OpenLux acceptance and visual quality have not been live verified; offline tests confirm the connector contract, not real generation results or upstream maxima. Check live `image.generate` before using the new fields. This archive does not deploy the API or update an installed Expert automatically.

The independent [character library](skills/character-library/SKILL.md) from 0.7 remains: explicit saving of selected owned images, immutable versions, search and metadata/archive management, fixed character bindings in supported image/video references, and video-specific temporary replacement. Character saves keep a stable idempotency key across uncertain outcomes and never create video feedback or action templates. Templates never create characters automatically. Server-side deduplication shares identical original image bytes within one account; existing image URLs retain their public-media behavior and historical duplicates are not deleted.

Character versions fix the selected inputs; current person-replacement output quality has not been verified. Stronger prompts do not guarantee the requested appearance. Upstream AI App role-slot semantics remain unknown unless documented by the actual public contract; do not infer face-replacement behavior from a local role label or image position.

Full-video and segment delivery, output-bound feedback, private action templates and strict input preflight remain available. The [production workflow](skills/video-generation/references/production-workflow.md) uses bounded 30–60-second polling, keeps full playback and action/audio checks, limits deep diagnostics to specific concerns, and preserves signed URLs exactly. It records each project's actual input provenance, checks selected-person appearance beyond generic labels, and requires reviewed continuity between dependent actions. The [template workflow](skills/video-generation/references/video-templates.md) saves only after the user explicitly chooses “satisfied and save”; every reuse creates a fresh task with new preparation, budget authorization and candidate review. Second-run time savings have not been measured.

Lifecycle management remains available through `get_account_usage`, `list_video_jobs`, `cancel_video_job` and `close_video_job`, with structured capacity/conflict errors in the stdio bridge. Plan and edit locally first; explicit submission creates one task, whose ID is saved and reused. Capacity errors lead to usage/list recovery, not repeated creation or switching keys. Cancel only a user-selected or explicitly authorized disposable draft that the server accepts as safe. Close only a particular stopped review/attention task the user explicitly abandons, when its current summary says `can_close:true`; pass its revision. Draft and active capacity each default to 10 concurrent records; eligible never-started drafts expire 24 hours after creation. Draft cancellation does not free active capacity; safe closure does. Neither deletes media. There is no remote draft-edit or create-idempotency API in this release, and uncertain create responses must be resolved before any new submission.

Lifecycle management requires server capability `video.replicate.lifecycle.version: 1`; closure additionally requires `lifecycle.closing` or `close_video_job` in the live remote tool list. A bundled bridge's tool list alone does not establish server support. Existing create→prepare remains compatible. Keep local project records outside the installation and release package, with no credentials. Public health/capabilities cannot verify a key; use supported native credential configuration and an authenticated read-only management request.

Delivery and templates require live `video.delivery` and `video.templates` capabilities marked available; characters additionally require `characters.library`. The remote catalog has 27 tools; the bundled stdio bridge adds local upload for 28. This package does not deploy those APIs or automatically update an installed Expert. Unsupported capabilities must be reported as unavailable; never strip selected character bindings to force an old server to accept a request. Templates and character records are account-private, immutable by version and archived without media deletion; names may repeat, so select by actual code and ID. Signed preview/download URLs are temporary and must not be kept in persistent project records.

Import this directory as the Expert package, connect its `lampstage` MCP dependency, and enter a personal API key from the Lampstage account page in WorkBuddy's token dialog. The root `.mcp.json` declares the streamable HTTP endpoint at `https://lampstage.com/api/mcp`; retain it when packaging. The bundled stdio bridge is available for environments using it. Provider credentials remain server-side.

For new reference-video jobs, the Expert checks `video.replicate` capability `modes.six_references`, studies the product and source actions, uploads the source plus 1–6 ordered, labeled references, and submits a semantic `segment_plan` of 1–8 complete windows. Each segment identifies before/after state, local action, source window and 4/5/6/8-second output. Common appearance/preservation instructions stay global. A segment can override references; a dependent segment can use an accepted real tail in place of one `start_state` reference. Preparation freezes existing inputs; it does not generate new state images. The [video skill](skills/video-generation/SKILL.md) and [MCP contract](references/mcp-contract.md) give the exact workflow and fields.

Rendering requires review of the actual references, plan and current quote, then the review token and budget. The account-wide scheduler permits at most three RunningHub requests at once. Inspect each candidate video before accepting or retrying it with `review_video_segments`; only accepted candidates may be assembled. Check the final encoded output at normal speed and confirm dimensions, audio and complete actions. Old jobs retain their recorded provider route. The six-image route and prior successful infant clothing case do not prove every new person, garment or scene will succeed on the first attempt.

The bundled stdio bridge's `upload_local_asset` accepts an explicitly supplied absolute file path and uploads a validated JPEG, PNG, WebP, MP4, MOV or WebM file through the authenticated asset API. It reads only that path, with 5 MiB image and 150 MiB video limits. The remote streamable HTTP MCP endpoint cannot read a client's local path; its `upload_asset` accepts a publicly readable `http(s)` URL. Real jobs require a healthy production API, database, storage and worker. Reimport this version to update an older installed Expert; local edits do not update installed packages automatically.
