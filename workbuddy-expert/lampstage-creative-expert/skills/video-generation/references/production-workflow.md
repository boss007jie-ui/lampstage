# 视频生产、检查与交付

用于正常视频复刻。提速来自减少发现延迟、重复诊断和下载错误；完整动作、人物与产品检查仍须执行。不要为速度跳过用户要求的逐段审核、接受已知缺陷、改变 `start_from_segment` 依赖，或擅自增加付费尝试。

## 提交前一次核清

在同一次首次分析中，逐段比较源片或明确计划中的**停顿、定格、结尾停留**与全局 `instructions`、该段 `instructions`、`after_state`：记录段号、源时间码、需保留的停留及依据，结论为通过／冲突／待核实。通用静图禁令只能限制“用静图替代必需动作”，不得误伤合法停顿；例如全局“Never hold a still frame”与某段“动作完成后 holds still”冲突，应按已确认动作与停留要求修正通用文字，不能只为消除关键词而删掉合法停留，也不得凭空增加停留或改变动作窗。

检查本地计划及既有流程实际取得的提示词。只有拿到本次服务端最终提示词时，才能记录该层已核验；不可见时写“上游最终提示词未核验”，不能以源码回归或能力声明冒充本次请求证据，也不为补这一项新增工具调用或人工关卡。明确冲突须先修正，再推进受影响的付费提交；确需用户决定的问题并入已有报价／预算确认，沿用仍有效的授权。素材和计划未变时复用核对记录。

在本地制作记录中整理素材 ID、版本、用途和顺序、完整原片动作表及景别变化/切镜与 punch-in、每段前态与后态、依赖、声音方式、必须保留项、禁止残留项、输出要求，以及本次明确的授权范围。先实际查看素材，缺少文件时核实，不把历史素材当成用户这次上传的文件。同次首轮分析中核对选定图片模型、视频模式与返回的供应商路线，检查完整场景起态是否同时符合源窗开场姿态、人物、衣物和机位；源片多次景别变化时，不写与其矛盾的“one continuous take”。需要制作的状态图先完成并审阅，视频 prepare 不会补图。已有妈妈、宝宝、商品和场景等分开的图片时，可按 [多参考图片流程](../../image-generation/references/multi-reference-images.md) 在授权内生成完整场景；无需要求用户先拼图。检查新图片接口的实际能力与方形比例限制，生成后仍须审阅。

本路径当前上游动作迁移App的提示词字段公开说明明确“动作迁移需要制作首帧图”。提交检查必须确认完整场景首帧已准备并审阅，且符合本单人物、商品、场景和开场姿态要求；只有产品平铺、宝宝、妈妈等分开的参考图不能视为已满足这个前提。合规场景首帧未准备或未审阅时，不得直接提交受影响的付费片段。该公开说明只证明首帧准备前提，不证明图1的内部连接、各槽权重或人物强绑定能力；补齐首帧也不保证换人成功。已有合规素材或免费抽帧可优先使用，另行付费制图仍须在明确授权内。

新项目建立自己的输入清单和计划文件。每条继承的人物、商品、服装、场景、音频及动作要求须注明来自本单素材、用户当前选择，或用户明确沿用的既有版本；同名文件、历史摘要和“上次用过”不能代替本次来源。素材相同且明确要复用时可保留原asset ID，不要求为了隔离而重复上传。发送前保存完整请求和摘要，逐项检查文字、参考图与当前选择是否冲突；更换人物后同时检查顶层、逐段覆盖参考和遗留外观文字，不能只换一张图或标题。不要通过未经允许读取或改写宿主长期记忆来“清理污染”。

同一连续操作跨段时，先说明下段状态如何成立。连续换装先生成并审阅首段，确认本次人物外观、产品、动作和实际后态，再推进后续段；不能为一次三路并发跳过该检查。默认按经审阅的前段实际尾帧设计接续；若选择独立片段，须有已审阅的独立起态证据，并说明其与前段终态、机位、服装状态兼容。没有合规起态图属于尚未解决的制作条件，不是取消依赖或直接提交全部片段的理由。不能擅自使用含旧人物/旧商品的源帧占位；先按已有授权补齐或调整方案，未补齐前不提交受影响的付费段。下载既有素材、本地抽帧等免费准备与另行生成状态图等可能收费步骤分开说明；不强制新增付费图片，确需付费时另取授权。

按当前能力与工具 schema 检查完整载荷，不创建探测任务。六参考合同的已知限制：

| 项目 | 提交前检查 |
| --- | --- |
| 参考图 | 每段有序 1–6 张、不重复；第一张为唯一完整场景 `start_state`，逐段覆盖也一样；角色符合 schema；标签非空、最多 80 个字符 |
| 分段 | 1–8 段；从零连续覆盖实测原片；生成时长 4/5/6/8 秒；双向时长比不超过 1.15 |
| 每段文字 | `instructions` 最多 1600，`before_state`、`after_state` 各最多 400；非空，不含换行、Tab、C0 控制字符或 DEL |
| 总体文字 | `title` 最多 80、全局 `instructions` 最多 2000；超长时先重新编辑和审阅，避免服务端静默截断关键要求 |
| 接续 | 仅依赖更早片段；该段恰好一张 `start_state`，将被已审阅的真实尾帧替换 |

上述字符长度按 JavaScript 字符串长度计算。标签也不得含上述控制字符。本地检查不能证明素材归属、服务器就绪或完整源时长已通过；仍以服务端准备结果为准。遇校验失败先定位字段，不用“比上次短一点”的猜测或新建有效探测任务来碰上限。

首次提交后保存 job ID 并沿用。除非素材版本或计划改变，复用已完成的素材核对，不反复全量下载与分析。

## 及时查询，按状态推进

使用同一 job ID 调用 `get_job`。正常 `queued`、`preparing`、`generating`、`assembling` 状态下，间隔 **30 秒**查询；连续无变化可退避到 **60 秒**，健康任务不要退避到数分钟。按一轮最多 **45 分钟**设本地观察截止时间，记录提交和每次发现状态变化的时间；截止只表示停止本轮自动轮询并报告现状，不代表任务失败或允许重提交。

网络错误或服务端限流遵守实际返回的重试指示；没有指示时最多做三次间隔 60 秒的只读重查，再报告连接问题并保留同一 ID。不要绕过限流。恢复查询不得自动重放 create/render/retry。

| 返回状态 | 下一步 |
| --- | --- |
| `review` 且有候选 | 立即检查新候选并进入既定审核流程，停止“仍在生成”的等待说明 |
| `review` 且无候选 | 核对参考快照和就绪片段，在已授权范围内准备本轮提交 |
| `attention` 或结果不明 | 保存原回执，按合同查询/核对原任务；不重建、取消或重新生成来探测结果 |
| `completed` | 下载并检查完整输出与分段，交付待验收内容；不推断用户满意 |
| `failed`、`cancelled` 或未知状态 | 说明实际状态和可行下一步，停止无意义轮询，不自动创建替代任务 |

每轮使用实际审阅的当前 token、候选哈希及报价；前轮 `review_token` 和费用批准不能自动覆盖变化。首次素材核对与既有预算确认中集中呈现起态、外观、景别、模型/模式冲突，不另加逐段调用或人工确认轮次。仅在用户事先明确授权的验收范围内检查通过后推进，并记录采用的标准、检查证据和授权来源。需要用户逐段确认时照做；已知缺陷、无法检查的关键动作以及超出范围的变化仍须明确处理。**额外付费重试必须单独获得明确授权**，不得默认连抽或同载荷重跑。

## 正常生产与深度诊断

在已经要求的候选正常速度完整播放中，检查每个必需动作是否完整发生、停顿是否出现在计划时点，以及要求的动作是否在结尾停留前完成，并检查非预期冻结及接点跳变。源片或明确计划中的动作前／动作中停顿也须保留，不能把所有停顿一律推到动作结束后。记录候选版本／哈希、时间码和通过／未通过／无法确认。合法内容停留与合成最多一个 30fps 交付帧（1/30 秒）的技术末帧保持分别记录；后者不能代替动作完成证据、延长创作停留或放宽 15% 时长规则。此检查复用既有播放，不增加生成、轮询或自动付费返工。

正常生产保留必要检查：素材 ID/角色/顺序与快照对应；每个新候选正常速度完整播放，核对身份、产品结构、每个必需动作及前后态、接点、手部和场景；按风险查看连续帧；核对解码、实际尺寸、时长及完整成片音轨。读取同一 `get_job` 中每段 `candidate_timing` 的 `status`、`reason`、实际/保留/交付时长及允许保留区间；`incompatible` 或 `unknown` 时先核实原因与素材，不重复提交相同无效审核、不自动 trim、变速或返工。该计算不证明动作、身份和观感合格。对已审阅且字节未变的候选复用记录，合成后仍检查接点、全片动作与实际音画对应。

人物替换按“本次选定参考／原片待替换人物／候选实际画面”分别核对，记录可见面部轮廓、五官相对形态、发型、年龄感、体态以及本次要求的衣着/饰物；这是外观对照，不作真实身份识别断言。遮挡、角度或证据不足时标为未通过确认/待用户确认，不能填通过。泛称“中国面孔”、短黑发、肤色相近或跨段看起来连贯，只是局部属性观察，不能独立支持“已符合所选人物形象”。提交前核查参考图、文字和源片的冲突；更换人物形象时，未经用户指示不得继承源片人物的衣着或发型，也不能同时要求匹配参考图又指定与之冲突的外观。抽查帧可以发现缺陷，不能据此把未经完整播放的动作或人物变化写成通过。已知接点衣襟复位、动作前移或机位变化，按缺陷记录，不能以各段单独可播放代替连续性验收。

分别记录 `candidate_media` 与官方 `output.media` 的实际规格。原始候选的704×1280/24fps等参数不能当成最终交付规格；正式合成有标准化步骤，当前路径目标为720×1280/30fps，但仍以本次成片实测为准。尚未合成时最终规格写未生成/待核验，不按候选参数预言，也不把能力声明当成实际成片证据。

6×6 图像 MAE 矩阵、逐帧版本差分、放大排查和反复整套参考比对仅在疑似串图、回归、明确缺陷或用户要求深度验收时使用，不作为每次生产的默认步骤。记录触发原因并只检查受影响项。

服务端参考图可能经过缩放/重编码，原上传文件哈希不同不等于串图。按实际 asset ID、用途、顺序、准备快照及必要的可视核对确认映射；候选下载则可与服务端提供的候选哈希核对。哈希只证明字节对应，不能证明内容正确。

MAE 只能描述所选图像的数值差异，不能单独证明身份一致、接缝自然、动作完整，也不能从两次不同生成推断“提示词导致了改善”。音频电平或声波只能支持有无信号、静音或潜在削波的技术判断，不能证明内容、句尾、原声保留或音画同步。未能播放或听音就标记“未检查”，交付待验收预览，不写通过。

## 下载与双份交付

签名媒体 URL 必须从最新工具响应中**逐字使用**，包括大小写、百分号编码和全部查询参数；不要重编码、手拼路径、改 `response-content-disposition` 或文件名。需要本地新文件名，只改保存路径。不要把 API 的 Bearer 凭据附加到媒体域名请求，也不把签名 URL 写入持久记录、诊断日志或发布包。

403 或确认过期时，同一 job 调用 `get_video_delivery`（成片/分段）、`get_job`（参考图/候选）或 `download_output`（完整输出）重取新链接，原样再下载一次。只用实际服务支持的接口；仍失败就报告下载问题并保留 ID，不修改签名或为下载失败重新生成。

**最终回答必须同时包含完整成片入口（尚未生成时明确缺失）和逐段入口。**

- 完整成片：给可点击的实际文件/最新官方输出入口，标明官方输出或本地 fallback、实际规格、待验收/已验收状态。
- 每个分段：按顺序给可点击入口、段号和对应动作；记录候选版本及已接受/待审阅状态。完整成片不能代替分段，分段也不能冒充完整成片。
- 官方合成失败：明确官方输出未生成及实际错误。已有经授权制作的本地 fallback 时仍交付它和全部分段，清楚说明其来源、实际规格、音频处理和未验证项；不能将 fallback 称为官方 completed。没有完整成片时明确“完整成片未生成”，给现有分段和恢复办法，不编造入口。
- 本地文件用绝对路径链接；临时远程入口提示可用同一 job ID 刷新。持久记录保存 ID、哈希、时间与本地路径，不保存签名 URL 或凭据。

服务端 completed、专家接受候选、客户满意是三个不同事实。交付后给出“满意并保存模板／只满意不保存／要修改”三个选择，按 [私人模板流程](video-templates.md) 绑定当前成片哈希记录实际反馈。只有用户明确选择满意并保存才执行保存，不发明接口或声称尚未完成的保存。
