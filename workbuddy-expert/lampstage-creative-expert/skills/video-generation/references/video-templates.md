# 私人视频模板与交付反馈

模板保存已完成作品的复刻配方，减少下一次重复拆解和规划。每次替换素材仍须准备、核对报价、生成和逐段检查；模板不保证相同画质或确定性复现。种子和模型构建信息未知时，不承诺逐像素复现。

C001人物档案与T001动作模板独立。保存人物不要求完整视频满意，保存动作模板也不自动保存人物。涉及人物版本或临时替换时，先读 [人物库流程](../../character-library/references/character-workflow.md)。

先查看实际服务的 `video.delivery`、`video.templates` 能力状态及工具合同；只有 `status: available` 才按该能力执行。旧服务没有这些能力时，说明暂不支持，保留任务 ID，不能凭本地工具列表宣称已保存模板。详细字段见 [MCP 合同](../../../references/mcp-contract.md)。正常检查和双份交付遵守 [生产流程](production-workflow.md)。

## 交付后由用户选择

1. 调用 `get_video_delivery {job_id}` 读取最新交付状态、完整输出和各段入口。`output: null` 表示官方完整成片尚未生成，分段不能填补它；按实际状态交付已有内容并处理合成问题。
2. 完成必要的全片与逐段检查，向用户同时提供完整视频和所有分段。签名 URL 原样使用；失效时读同一交付接口刷新，不能改签名参数。
3. 给用户三个明确选择：**满意并保存模板**、**只满意，不保存**、**要修改**。用户只说“完成了”“收到”或任务状态 completed，均不能推断满意，更不能自动保存。已知有缺陷的当前结果不得替用户标满意。
4. 仅当 `can_feedback: true` 且有当前 `output_sha256` 时，按用户实际选择调用 `submit_video_feedback`。`satisfied_save_template` 还要求 `template_save_supported: true`。反馈必须绑定刚交付并确认过的完整成片哈希；输出已变化时重新交付确认，不能静默替换哈希重发。

| 用户选择 | `decision` | 效果 |
| --- | --- | --- |
| 满意并保存模板 | `satisfied_save_template` | 保存账户私人模板；可用用户给定名称/分类，缺省名称由服务端生成 |
| 只满意，不保存 | `satisfied` | 只记录反馈 |
| 要修改 | `needs_changes` | 记录具体问题，不自动产生付费重试 |

返回真实 `template` 和 `version_id` 后才告知“已保存”，记录编号、内部 ID、版本和来源任务。`template_id` 只用于用户明确选择“存为已有模板的新版本”；首次保存不要猜一个 ID。反馈备注不放密钥、签名 URL 或本地私密路径。服务器对同一任务同一成片重复保存防重，但网络结果不明仍先读取交付反馈核对，不盲目重复 POST。修改需求另行规划，额外付费尝试另取明确授权。

## 先找模板，再规划

用户要求继续已有模板、按编号复刻，或提供同一原片时，先查询：

- 按源：`list_video_templates {source_asset_id}`，或已知原片字节 SHA256 时 `{source_sha256}`。同文件重新上传可由服务端按哈希匹配。历史素材哈希未知时不要猜；读取列表不会替历史文件下载算哈希。
- 按编号/名称：分页读取账户模板，在返回的 `code`/`name` 中查找；没有编号查询参数，不发明参数。默认只查 active；只有需要归档项时才查询 archived/all。
- 名称重复时展示实际编号、名称、时长和可用预览供选择；不能取第一条。列表游标原样传回，不能把单页末尾当作没有更多模板。
- `T001` 是展示编号，调用详情/更新时使用返回的内部 `id`。不要把编号直接当模板 ID。

选定后调用 `get_video_template {template_id,version_id?}`。未指定版本时服务端选最新；将返回的 `selected_version.id` 固定为本次计划版本，不能在确认后悄悄切到新版本。归档模板必须先按用户要求恢复后才能复用；不要自动恢复。

## 用清洁配方创建新任务

读取 `selected_version.create_payload`，其中分段字段是 **`segment_plan`**。逐项替换并实际检查本次的产品、人物、场景和状态参考图，保持槽位角色、顺序及作用清楚；不要误用旧商品照片或旧候选尾帧。新任务逐段有效参考必须以唯一 `start_state` 开头；旧模板顺序不符时，不悄悄重排历史版本或绕过模板结构签名，先作为新计划按当前合同重新审阅。

兼容 `recipe_schema_version:1|2`。schema2的绑定槽由服务端解析回实际素材ID，并返回固定 `character_version_id,image_index`；`selected_version.character_bindings` 给出人物编号、版本和顶层/分段槽位。保持绑定字段，用该版本的实际图片ID。用户明确选择临时替换时写 `character_version_id:null` 且不带 `image_index`，不调用人物保存；原绑定槽直接省略字段会被拒绝。不能静默去掉绑定来兼容旧服务。归档人物只有已由当前明确选定动作模板版本固定的原绑定可以沿用，不能作为新人物选择；动作模板本身的归档恢复规则不变。

允许替换素材 ID、参考标签、标题、总体要求和分段动作文字。关联同一模板版本时须保留源视频身份/哈希、工作流、音频策略、每段时间窗、目标时长、依赖和参考槽角色顺序。若更换原片内容、改变时长、音频策略、依赖或槽角色，按新结构重新规划，不强行套用原版本；满意后可另建模板。同源并不代表同结构。

本地校验后，向用户说明将复用的编号/版本、素材替换、保留结构及本次计划。在用户明确提交范围内，仅发送清洁创建字段：

```text
create_video_job {
  template_version_id: selected_version.id,
  ...reviewed_create_payload
}
```

`reviewed_create_payload` 顶层仅含 `source_asset_id`、`product_asset_id`、`title`、`instructions`、`preserve_audio`、`generation_mode: "six_references"`、`reference_assets`、`segment_plan`；人物绑定字段仅在相应参考图条目中。音频选项须为布尔值，提供的标题须非空，不让错误类型或空白标题静默变成服务端默认值。不得展开旧 job 对象，复制 `consent`、review token、供应商回执、permit、candidate、accepted、实际 tail、attempt 或 history。旧候选的接受状态和旧报价不能用于新任务。创建不自动 prepare 或 render；保存新 job ID，再按新任务走准备、素材快照核对、当前报价/预算授权、生成、逐段检查、接受与合成。

有接续依赖时，原 `start_from_segment` 结构可复用，实际尾帧必须来自这次新任务已接受的前段。不能为提速去掉依赖或沿用旧作品尾帧。

## 维护与边界

`update_video_template` 支持名称、分类、归档/恢复；名称非空且不超过80字符，分类不超过40字符。用户明确要求时可执行这些可逆更新。模板和版本为当前账户私有，版本不可修改；不提供硬删除。归档不删除媒体、不释放草稿或活动配额。模板保存引用和小型配方，不复制一套视频；仍不能承诺无限存储或自行清理原媒体。

将新成果加入已有模板版本，必须是同源同结构的新任务、完整输出已完成且所有候选被接受，并由用户明确满意及选择保存为新版本。遇404、归档冲突、结构冲突、输出变化或尚未完成等错误，保留原任务和选择，核对实际状态；不通过去掉 `template_version_id` 偷偷绕过关联校验。只有用户接受新结构后才将它作为独立新计划提交。
