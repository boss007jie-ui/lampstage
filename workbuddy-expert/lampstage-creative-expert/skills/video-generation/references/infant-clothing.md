# 婴幼儿穿衣视频复刻指南

版本 1.2 · 2026-10-16。适用于以真实参考视频保留成人与宝宝互动、穿衣动作，并更换人物、服装或床面颜色的项目。来自既有项目复盘；用于减少已知错误，尚无多素材统计证明普遍成功率，不能承诺一次必成。

正常生产同时遵循[生产、检查与交付规则](production-workflow.md)：及时查询同一任务，保留完整动作与声音检查；只有出现明确问题才进入深度量化诊断。效率优化不得改变用户逐段审核要求或把已知缺陷自动放行。

## 1. 先锁定本单事实与工具能力

按用户本次已确认要求建立[制作记录](replication-review-template.md)：原片、产品图、人物参考、只改什么、保留什么、动作顺序、音频方式、完整度要求、预算及已授权范围。已有信息直接沿用，只补真正影响执行的未知项。

“已有信息”仅指本单已核对事实或用户明确沿用的版本。新项目单独记录每项来源；历史产品参数、妈妈衣着、宝宝发饰、床品和动作例子不能默认带入。保存实际提交的完整载荷与摘要，将文字、参考图和本次选择逐项核对；仅看到提示词接近2000字符或画面相似，不能诊断为记忆污染。

**已确认事实优先于旧脚本和不完整图片推断。** 用户确认新旧衣物结构及穿法相同，就保持原穿法；平铺图没显示扣子不代表没有扣子，不得自行改成另一种穿法。只有新证据明确冲突或产品确实换了结构，才核实并重新映射动作。工期紧、旧方案已花费，都不能让错误脚本覆盖确认过的结构；也不要让客户再次确认同一事实。

记录视频流时长、尺寸、帧率、帧数、音轨与开头结尾要求。若要求完整保留，不能默默裁掉片头、尾部、变速或跳过动作；连 0.2 秒的取舍也要按本单要求判断，别套用历史案例的允许范围。

提交前查实际工具合同。新任务使用 `six_references` 时，`capabilities` 中 `video.replicate` 条目须有 `modes.six_references` 和 `status: available`。参考图为完整有序的 1–6 张，每张填写 asset ID、角色与具体标签；商品图不固定占第一张。起态、终态图只是通用参考，并非已验证的专用首尾帧控制。五张图分担起态、宝宝、斜襟结构、商品、妈妈职责，是本项目提示约定，不得宣称私有工作流对各槽有固定权重。不得悄悄舍弃、合成或重复素材来凑输入。连接器有语义分段与候选审核，但没有床面蒙版或新口播混音工具。**上传了锚点不等于模型已使用锚点，写了提示词不等于实现了控制。** 能力不足而影响必要条件时，先交付制作方案与具体缺口，暂停相关生成；不得自行改回旧模式或反复付费试缺失能力。

后面的局部改色及混音规则也可供具备相应工具的制作流程使用；它们不是本包新增的软件功能。通用 `available` 或健康状态不代表这些功能已经存在。

本路径当前动作迁移App提示词字段的公开说明明确“动作迁移需要制作首帧图”。提交前须准备并审阅符合本单变更与开场姿态的完整场景首帧；仅有产品平铺、宝宝、妈妈三张独立参考不满足该前提。可按 [多参考图片流程](../../image-generation/references/multi-reference-images.md) 将人物、商品和场景分别提交，在授权内生成完整场景图，不要求用户先拼图；须检查当前图片能力、比例及实际输出。首帧未准备或未审阅，不得直接提交受影响的付费片段。此说明不披露图1内部连接或参考权重，也不保证增加首帧后一定换人成功。

## 2. 分清参考的职责

| 参考 | 负责什么 | 不能代替什么 |
| --- | --- | --- |
| 宝宝身份参考 | 面部、发型、肤色、头身尺度；首段与后续角度核对 | 不能只靠“有卷发”或“检测到脸”判断同一人 |
| 妈妈参考 | 出镜身份、发型、体型、肤色、衣着；包括手臂/袖口近景 | 只换开头头像不代表整片妈妈已换 |
| 商品结构参考 | 正面、斜襟方向、扣位、袖口、裤腰、图案与花朵所在面 | 不让截图 UI、色卡或不相关道具成为商品；缺失信息不能推翻用户确认 |
| 最终穿好状态 | 终态产品外观与穿着效果 | 不能证明穿袖、扣合或开→合操作发生过 |
| 原动作视频 | 操作顺序、速度、手的接触、相机运动与时间关系 | 不让生成模型自行重编穿衣过程 |
| 场景参考 | 姿态、头颈胸连接、成人托抱接触、机位、光线和床面 | 场景相似仍要单独核对身份与产品 |

开场是横抱、后仰或侧转，而身份图是正面仰卧时，本路径动作迁移的完整场景首帧仍须匹配开场姿态与本单人物、衣服、床色要求并经审阅；不能以独立身份照替代。优先已有合规素材及免费抽帧，额外付费图片准备须在授权内，且每段最多六张参考。准备步骤不会自行生成首尾状态图。局部贴头曾产生滑动和不自然头身关系，不作为默认补救；跨姿态的人脸不要靠叠化掩盖。所有参考要互相一致，别让含旧衣服、旧人物或旧床色的图覆盖本轮变更。妈妈近景还须检查袖口与饰物；曾有浅绿手镯和蕾丝袖口残留。

不得复制历史工作流的固定触发词、图片编号或输入槽位顺序。任何适配参数以当前实际合同为准。

人物外观验收须同时对照本次所选参考、原片人物与候选，不以“中国面孔”“短黑发”“没有发带”或前后段看似连贯判定已符合目标形象，不作真实身份识别断言。记录可见轮廓与五官相对形态、发型、体态、所需衣着/饰物；看不清的项标为未通过确认/待用户确认。参考图与文字指定衣着、发带或发型冲突时核对本单要求；更换人物形象不能未经用户指示继承源片人物外观。参考图ID/哈希正确只证明输入对应，不能证明生成结果采用了该外观。

## 3. 按变更项决定返工范围

| 本次更换 | 应处理的镜头 | 可复用内容及验收重点 |
| --- | --- | --- |
| 只换宝宝 | 所有出现宝宝脸或身体的相关镜头，包含开场与遮挡/侧转 | 可复用动作、产品、妈妈设定和剪辑方案；含旧宝宝的画面不能直接交付。检查身份、头颈身体联动与遮挡 |
| 只换妈妈 | 开头出镜以及肤色、手臂、袖口或衣着受影响的近景 | 不相关且仍匹配的镜头可复用；检查开头与操作近景的一致性 |
| 只换床单颜色 | 同一已通过底片上的床面区域 | 优先局部后期，保留人物、服装、动作、音轨、纹理、阴影；无局部工具时说明缺口，不默认重新生成整片 |
| 换宝宝衣服 | 所有露出旧衣服、花纹或扣边的镜头 | 同结构保留穿法；先验收新结构参考，再检查旧款残留、正反面和扣位，不能只换封面或结尾 |

同时换多项时先建立一套一致的参考和镜头影响表，再制作；不要拼接身份、衣服或床色不相容的旧镜头。保留已通过旧版本，不反复在旧成片上累积生成误差。

## 4. 动作完整性决定分段和验收

为每个必须动作写出“前态 → 接触/操作 → 后态”。例如：第一只袖子未穿 → 成人托住宝宝手、将手送入袖口 → 手从袖口露出。静止展示、穿好后的反应、突然闭合的衣襟，都不能补掉中间操作。

动作表来自本单原片与用户确认，不套用另一条片子的固定顺序。若原片结尾包含开裆或露尿布展示且本单要求保留，不能擅改成全封闭或宣称所有内腿扣已扣好。

`segment_plan` 按动作语义切窗：穿袖、扣衣、落床、翻身等关键动作完整落在一个窗口，明确前态、操作和后态，同次记录源片景别变化及 punch-in；文字不能同时要求与原片不符的连续单镜头。源片须从头到尾无缺口覆盖；输出时长为 4/5/6/8 秒，轻微重定时不得超过 15%。每段有效参考第一张须为唯一经审阅的完整场景 `start_state`，与该窗开场姿态、衣物和机位吻合。不要把两袖和扣襟硬塞进短窗；已接受案例拆为两袖 5 秒、斜襟/下摆 6 秒、裤前/腰部 5 秒。具体窗口仍以本单源动作决定。

独立且已审阅的片段可由服务端按账户统一最多三并发提交；依赖前段真实尾帧的片段须等该候选播放审阅并接受后才就绪。对坏段用候选哈希定点返工，已通过片段复用；不得因超时重建任务。

连续换装必须逐接点列出“前段实际后态 → 下段所需前态”和接续方式，并先审首段，再推进后续付费段。缺少合规起态图不能直接改为三段独立并发；先解决起态条件或调整计划。选择独立生成须有已审阅的独立起态和连续性依据。优先利用已有且经用户确认的参考或本次已审阅的实际尾帧；免费抽帧等准备不等于获准另行付费生成状态图，不强制购买新图。语义边界优先于等分时长；总长度/时长比合法不代表切窗合理，不能把穿左袖等同一必要动作切成两段后又在前段文字里宣称已经完成。输出若提前扣好、下一段又打开，接点明确失败，不自动接受或仅强化提示词重跑；先核对源窗口、参考、实际载荷与候选证据。

每段检查前导参考照片闯入、动作压缩/跳过、静止、倒带、背景突变、衣物变形。双人画面锁定宝宝目标，识别漏掉时不允许转而替换成人。按可见动作匹配时间，不因输出秒数不同就机械拉伸。裁切必须保留必要动作及用户要求的覆盖范围。

## 5. 拼接、床面与声音

**接点：** 按宝宝姿态、脸朝向、成人手、衣襟、枕头及床纹选稳定位置。优先自然直接切；只有姿态相近时试短叠化，逐帧排查双眼、双嘴、双头和手/衣服重影。必要时仅重做相邻失败段，但先确认工具能做到且费用在授权内。

**床面：** 身份与动作先通过，再做局部改色。只有完全相同底片、尺寸和帧序的蒙版缓存可直接复用；新画面须重建、跟踪和验收。结合床面区域、位置与连通关系保护手、指尖、皮肤、袖口、衣服及枕头，保留纹理、明暗与阴影。衣物掀起后的缝隙和手部遮挡需连续检查。历史 HSV 数值或静态单帧蒙版不代表整段稳定。

**声音：** 保留原音频时，组装只挂一次原音轨，避免混入重复模型音频；输出时长仍需覆盖所需声音。使用新口播且有混音工具时，按动作逐句定位，保留完整句尾；原案例中逐句 PCM 混音可作方法参考，但本包不提供该脚本。检查实际输出信号并正常听音、核对时序，不能用“音轨存在”、进程成功或 ASR 文本代替听音。无法听音时明确标为待检查。

## 6. 失败只修原因对应的部分

| 现象 | 优先核查与处理 |
| --- | --- |
| 穿袖、扣合、翻身被跳过 | 查动作表与切窗；重设完整动作窗口，不能靠延长时长或终态画面冒充动作 |
| 开场不像同一宝宝、照片构图闯入 | 查实际身份输入、整幅场景参考和源首帧姿态；重做受影响开场 |
| 头身假、托抱不成立、脸层滑动 | 检查整幅姿态和接触，不回到局部贴头或跨姿态叠化路线 |
| 成人被当作宝宝 | 检查目标映射与跟踪，漏检就停止该方案，不自动换目标 |
| 服装结构或旧花纹残留 | 先修冲突参考和结构定义，再处理露出旧产品的片段，别持续堆否定词 |
| 床色跳动、手或袖口误染 | 修局部遮罩及前景保护；必要时换跟踪分割方法或仅重做受影响段 |
| 接点跳位/重影 | 重选稳定切点，缩短或取消叠化，再判断是否需要付费重做 |
| 音轨存在却静音、句尾丢失 | 查实际信号、混音与截断位置，修音频后重新编码验收 |

连续尝试未改善核心动作或自然观感时停止加码，记录原因并重设参考或窗口。不要自动连抽，不因一个缺陷推翻全部已通过镜头。

## 7. 费用与交付门槛

旧模式的首尾参考图生成或另行选择的图片制作可能收费，须在已有授权范围内执行。六图准备仅冻结已上传参考并整理原片，不自动生成状态图。渲染前展示实际参考图、角色/标签、语义窗口、当前币数报价与未知费用，并使用该次审阅的 `review_token`。`max_coins` 在上游价格不明时不是硬封顶。排队、查询超时和进程仍在心跳均不证明生成失败：保存同一个 job ID，查询原任务并检查实际进展，不用重建任务解决等待。失败原因及上游提交状态未明时，不重复提交。候选须播放后用 `candidate_review_token` 与哈希接受或返工，全部接受后才合成。

每轮核对：已花费 + 已提交未结算 + 下一次报价 + 预计后期/人工 + 缓冲 ≤ 总预算。未知费用标待核实；失败或未用于成片的付费输出也记账。使用当前实际报价，不将历史某账户充值比例、单例币数或纯生成成本当成固定全包价格。

交付前在**实际编码成片**上完成：

- 正常速度完整观看；身份、产品、动作顺序和每步前后态符合本单要求。
- 开头、接触、遮挡、转场与结尾做连续帧或密集帧检查；头颈肩、手部受力、光线、模糊与表情自然。
- 床面稳定、前景无误染；无旧产品残留；片头尾段与要求覆盖一致。
- 核对视频流时长、尺寸、帧率、帧数、音画对应并完整解码；实际听音、检查句尾。
- 原始候选与正式合成规格分开填写；候选704×1280/24fps不能代替最终输出证据。正式合成当前目标720×1280/30fps，仍检查本次成片实际媒体信息，未合成时不预测实测结果。
- 记录检查方式与结果；未能播放、听音或访问素材的项目写“未检查”，不能写通过。任务 completed 后可作为“待验收预览”返回，最终交付要有实际验收结论。

单个技术检查不能替代用户观感。后续至少积累多条独立素材，保留完整尝试数与失败记录，再按统一口径分析首次验收率、最终交付率、重试数、时间和总成本。

交付时同时提供完整成片与按顺序排列的分段入口。官方合成失败但已有本地兜底时，仍给出可用的本地成片和分段，说明音频处理、实际规格、已知缺陷及未检查项；不把兜底标为官方成功，也不从 completed 推断客户满意。MAE 差异不能证明提示词产生了因果效果，音频电平不能证明内容完整或音画同步。
