# 婴幼儿穿衣视频复刻指南

版本 1.0 · 2026-10-14。适用于以真实参考视频保留成人与宝宝互动、穿衣动作，并更换人物、服装或床面颜色的项目。来自两份既有项目复盘；用于减少已知错误，尚无多素材统计证明普遍成功率，不能承诺一次必成。

## 1. 先锁定本单事实与工具能力

按用户本次已确认要求建立[制作记录](replication-review-template.md)：原片、产品图、人物参考、只改什么、保留什么、动作顺序、音频方式、完整度要求、预算及已授权范围。已有信息直接沿用，只补真正影响执行的未知项。

**已确认事实优先于旧脚本和不完整图片推断。** 用户确认新旧衣物结构及穿法相同，就保持原穿法；平铺图没显示扣子不代表没有扣子，不得自行改成另一种穿法。只有新证据明确冲突或产品确实换了结构，才核实并重新映射动作。工期紧、旧方案已花费，都不能让错误脚本覆盖确认过的结构；也不要让客户再次确认同一事实。

记录视频流时长、尺寸、帧率、帧数、音轨与开头结尾要求。若要求完整保留，不能默默裁掉片头、尾部、变速或跳过动作；连 0.2 秒的取舍也要按本单要求判断，别套用历史案例的允许范围。

提交前查实际工具合同。`direct_references` 只在 `capabilities` 数组中 `id` 为 `video.replicate` 的条目标明 `modes.direct_references` 且 `status` 为 `available` 时可用：商品图固定为 Picture 1，另外两张按 `reference_assets` 顺序成为 Picture 2、3，须各有明确 `role` 和 `label`（如“宝宝”“妈妈”）。它们是通用参考图，不是独立的宝宝/妈妈身份控制槽；第四张独立场景图不能再添加。场景应占用两张中的一张、出现在已确认的参考图里，或保留原片场景。不得悄悄舍弃、合成或重复素材来凑输入。连接器仍没有自定义分段时间轴、床面蒙版、指定单段提交或新口播混音工具。**上传了锚点不等于模型已使用锚点，写了提示词不等于实现了控制。** 能力不足而影响必要条件时，先交付制作方案与具体缺口，暂停相关生成；不得自行改回旧模式、换底层工作流或反复付费试缺失能力。

后面的分段、局部改色及混音规则也可供具备相应工具的制作流程使用；它们不是本包新增的软件功能。通用 `available` 或健康状态不代表这些功能已经存在。

## 2. 分清参考的职责

| 参考 | 负责什么 | 不能代替什么 |
| --- | --- | --- |
| 宝宝身份参考 | 面部、发型、肤色、头身尺度；首段与后续角度核对 | 不能只靠“有卷发”或“检测到脸”判断同一人 |
| 妈妈参考 | 出镜身份、发型、体型、肤色、衣着；包括手臂/袖口近景 | 只换开头头像不代表整片妈妈已换 |
| 商品结构参考 | 正面、斜襟方向、扣位、袖口、裤腰、图案与花朵所在面 | 不让截图 UI、色卡或不相关道具成为商品；缺失信息不能推翻用户确认 |
| 最终穿好状态 | 终态产品外观与穿着效果 | 不能证明穿袖、扣合或开→合操作发生过 |
| 原动作视频 | 操作顺序、速度、手的接触、相机运动与时间关系 | 不让生成模型自行重编穿衣过程 |
| 场景参考 | 姿态、头颈胸连接、成人托抱接触、机位、光线和床面 | 场景相似仍要单独核对身份与产品 |

开场是横抱、后仰或侧转，而身份图是正面仰卧时，检查是否需要与源首帧姿态一致的整幅场景参考；额外图片准备必须经用户明确选择，且仍受三个图片输入的容量约束。`direct_references` 不需要先生成首尾帧。局部贴头曾产生滑动和不自然头身关系，不作为默认补救；跨姿态的人脸不要靠叠化掩盖。所有参考要互相一致，别让含旧衣服、旧人物或旧床色的图覆盖本轮变更。

不得复制历史工作流的固定触发词、图片编号或输入槽位顺序。任何适配参数以当前实际合同为准。

## 3. 按变更项决定返工范围

| 本次更换 | 应处理的镜头 | 可复用内容及验收重点 |
| --- | --- | --- |
| 只换宝宝 | 所有出现宝宝脸或身体的相关镜头，包含开场与遮挡/侧转 | 可复用动作、产品、妈妈设定和剪辑方案；含旧宝宝的画面不能直接交付。检查身份、头颈身体联动与遮挡 |
| 只换妈妈 | 开头出镜以及肤色、手臂、袖口或衣着受影响的近景 | 不相关且仍匹配的镜头可复用；检查开头与操作近景的一致性 |
| 只换床单颜色 | 同一已通过底片上的床面区域 | 优先局部后期，保留人物、服装、动作、音轨、纹理、阴影；无局部工具时说明缺口，不默认重新生成整片 |
| 换宝宝衣服 | 所有露出旧衣服、花纹或扣边的镜头 | 同结构保留穿法；先验收新结构参考，再检查旧款残留、正反面和扣位，不能只换封面或结尾 |

同时换多项时先建立一套一致的参考和镜头影响表，再制作；不要拼接身份、衣服或床色不相容的旧镜头。保留已通过旧版本，不反复在旧成片上累积生成误差。

## 4. 动作完整性决定分段和验收

为每个必须动作写出“前态 → 接触/操作 → 后态”。例如：第一只袖子未穿 → 成人托住宝宝手、将手送入袖口 → 手从袖口露出。静止展示、穿好后的反应、突然闭合的衣襟，都不能补掉中间操作。

动作表来自本单原片与用户确认，不套用另一条片子的固定顺序。若原片结尾包含开裆或露尿布展示且本单要求保留，不能擅改成全封闭或宣称所有内腿扣已扣好。

具备分段工具时，按动作语义切窗：穿袖、扣衣、落床、翻身等关键动作尽量完整落在一个窗口；必要时留对齐余量。历史短窗/重叠秒数只能作试验起点，不是固定参数；实际模型支持的时长与原动作优先。当前自动分段返回后也要检查动作是否被截断，不能写个时间码就声称服务端已采用。

若支持单段制作，先完成最关键的一个正式镜头，验收后扩展到其余受影响镜头；它应属于计划成片，不额外增加无目的的付费试片。若接口不支持单段控制，不能假装已按单段策略提交。

每段检查前导参考照片闯入、动作压缩/跳过、静止、倒带、背景突变、衣物变形。双人画面锁定宝宝目标，识别漏掉时不允许转而替换成人。按可见动作匹配时间，不因输出秒数不同就机械拉伸。裁切必须保留必要动作及用户要求的覆盖范围。

## 5. 拼接、床面与声音

**接点：** 按宝宝姿态、脸朝向、成人手、衣襟、枕头及床纹选稳定位置。优先自然直接切；只有姿态相近时试短叠化，逐帧排查双眼、双嘴、双头和手/衣服重影。必要时仅重做相邻失败段，但先确认工具能做到且费用在授权内。

**床面：** 身份与动作先通过，再做局部改色。只有完全相同底片、尺寸和帧序的蒙版缓存可直接复用；新画面须重建、跟踪和验收。结合床面区域、位置与连通关系保护手、指尖、皮肤、袖口、衣服及枕头，保留纹理、明暗与阴影。衣物掀起后的缝隙和手部遮挡需连续检查。历史 HSV 数值或静态单帧蒙版不代表整段稳定。

**声音：** 保留原音频时，组装只挂一次原音轨，避免混入重复模型音频；输出时长仍需覆盖所需声音。使用新口播且有混音工具时，按动作逐句定位，保留完整句尾；原案例中逐句 PCM 混音可作方法参考，但本包不提供该脚本。检查实际输出信号并正常听音、核对时序，不能用“音轨存在”、进程成功或 ASR 文本代替听音。无法听音时明确标为待检查。

## 6. 失败只修原因对应的部分

| 现象 | 优先核查与处理 |
| --- | --- |
| 穿袖、扣合、翻身被跳过 | 查动作表与切窗；重设完整动作窗口，不能靠延长时长或终态画面冒充动作 |
| 开场不像同一宝宝、照片构图闯入 | 查实际身份输入、整幅场景参考和源首帧姿态；重做受影响开场 |
| 头身假、托抱不成立、脸层滑动 | 检查整幅姿态和接触，不回到局部贴头或跨姿态叠化路线 |
| 成人被当作宝宝 | 检查目标映射与跟踪，漏检就停止该方案，不自动换目标 |
| 服装结构或旧花纹残留 | 先修冲突参考和结构定义，再处理露出旧产品的片段，别持续堆否定词 |
| 床色跳动、手或袖口误染 | 修局部遮罩及前景保护；必要时换跟踪分割方法或仅重做受影响段 |
| 接点跳位/重影 | 重选稳定切点，缩短或取消叠化，再判断是否需要付费重做 |
| 音轨存在却静音、句尾丢失 | 查实际信号、混音与截断位置，修音频后重新编码验收 |

连续尝试未改善核心动作或自然观感时停止加码，记录原因并重设参考或窗口。不要自动连抽，不因一个缺陷推翻全部已通过镜头。

## 7. 费用与交付门槛

旧模式的首尾参考图生成或另行选择的图片制作可能收费，须在已有授权范围内执行。`direct_references` 的准备仅冻结参考图并自动切分原片，不生成首尾帧。渲染前展示三张实际参考图、角色/标签、切分窗口和当前币数报价，并取得明确预算同意。排队、查询超时和进程仍在心跳均不证明生成失败：保存同一个 job ID，查询原任务并检查实际进展，不用重建任务解决等待。失败原因及上游提交状态未明时，不重复提交。

每轮核对：已花费 + 已提交未结算 + 下一次报价 + 预计后期/人工 + 缓冲 ≤ 总预算。未知费用标待核实；失败或未用于成片的付费输出也记账。使用当前实际报价，不将历史某账户充值比例、单例币数或纯生成成本当成固定全包价格。

交付前在**实际编码成片**上完成：

- 正常速度完整观看；身份、产品、动作顺序和每步前后态符合本单要求。
- 开头、接触、遮挡、转场与结尾做连续帧或密集帧检查；头颈肩、手部受力、光线、模糊与表情自然。
- 床面稳定、前景无误染；无旧产品残留；片头尾段与要求覆盖一致。
- 核对视频流时长、尺寸、帧率、帧数、音画对应并完整解码；实际听音、检查句尾。
- 记录检查方式与结果；未能播放、听音或访问素材的项目写“未检查”，不能写通过。任务 completed 后可作为“待验收预览”返回，最终交付要有实际验收结论。

单个技术检查不能替代用户观感。后续至少积累多条独立素材，保留完整尝试数与失败记录，再按统一口径分析首次验收率、最终交付率、重试数、时间和总成本。
