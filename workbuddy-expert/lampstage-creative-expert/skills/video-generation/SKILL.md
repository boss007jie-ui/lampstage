# Video generation

For every video project, read [production-workflow.md](references/production-workflow.md) for preflight, 30–60 second bounded polling, normal versus deep inspection, signed downloads and full-video-plus-segment delivery. Read [video-templates.md](references/video-templates.md) before looking up, reusing or saving a private template. These guides do not relax user review requirements, paid authorization or dependency checks.

在既有首次分析中，必须核对源片或明确计划中的停顿、定格、结尾停留，与全局 `instructions`、逐段 `instructions` 和 `after_state` 是否一致。记录段号、时间码、依据和通过／冲突／待核实；只对实际取得的服务端最终提示词标记已核验。明确冲突先修正再提交受影响的付费片段，问题集中进入已有报价确认，不增加正常调用或确认轮次。在既有候选播放中确认停顿出现在计划时点、结尾停留前完成要求的动作，并检查非预期冻结与接点跳变；源片或明确计划中的动作前／动作中停顿也须保留。具体边界按生产指南执行。

Record the source of every retained requirement in this project's input manifest; only carry historical assets/text explicitly selected for this job. Continuous operations need reviewed state continuity at each segment boundary. Missing valid start-state images must be resolved before affected paid work, not used as a reason to parallelize. Compare each selected person's visible appearance with the original and candidate; broad demographic/hair descriptions alone cannot establish a successful replacement. Sampled frames can reveal defects but cannot replace full playback.

When saving or reusing a person, a C-code or bound character slot, read [character-library](../character-library/SKILL.md). An explicitly chosen character can be saved without a completed or satisfactory film. C-code saving and T-code saving never trigger each other. Fixed-version references use `character_version_id` plus `image_index`; explicit null means a temporary character replacement with no saved profile. Ordinary unbound references remain compatible.

For 婴儿服装、童装、宝宝穿衣、换宝宝、换妈妈 or 床单换色, read [infant-clothing.md](references/infant-clothing.md) and use the [review record](references/replication-review-template.md).

1. Study the source motion and product before writing a plan. Confirm what changes and what stays. Preserve the original dressing method when product structure is unchanged. Record each complete action with its before state, contact/operation and after state, plus source camera cuts and punch-ins. Do not infer a different fastening method from a flat product photo. Check the actual opening pose and garment state against the reviewed complete-scene start image; inspect existing assets for conflicting old people, clothes or scenery. Resolve source motion versus text conflicts such as multiple punch-ins versus “one continuous take” in this same first analysis. Any needed state image must already be uploaded and reviewed; preparation does not generate multi-reference state images.
2. Check `health`, `capabilities`, and live tool schemas. For new six-image work require `video.replicate` with `status: available` and an enabled `modes.six_references` capability entry. Fix the selected image model, video generation mode and actual returned provider route in the project record; an unexpected change requires review, not automatic switching. Do not silently fall back to the old three-image route. Upload the motion video and 1–6 distinct, ordered references. When using the bundled stdio bridge and the user supplies an absolute local path, use `upload_local_asset` with that exact path and kind; do not scan or choose files. It validates regular JPEG/PNG/WebP images up to 5 MiB and MP4/MOV/WebM videos up to 150 MiB before authenticated upload. The remote HTTP MCP endpoint cannot read local paths; use its URL-based `upload_asset` only for a publicly readable `http(s)` URL. Each reference is `{asset_id, role, label}`, with role `product|character|scene|product_detail|start_state|end_state`. Each effective segment list must begin with exactly one reviewed, complete-scene `start_state`; a segment override replaces the whole list and must also meet this rule. `product_asset_id` is optional; it does not reorder slots or mean product replacement. Use only images that serve a documented purpose. State images are ordinary references, not proven dedicated first/last-frame controls. The five-slot convention from one infant clothing project is project-specific; no fixed per-slot weighting has been verified.
3. Build `segment_plan` with 1–8 complete semantic windows in source order, from zero through the whole source without gaps or overlaps. Each entry needs `start`, `source_duration`, output `duration` of 4/5/6/8 seconds, local `instructions`, `before_state`, and `after_state`. The larger of `source_duration/duration` and `duration/source_duration` may be at most 1.15. 完整保留必需动作及源片或明确计划中的合法停顿；不得用静图替代动作、静默丢失动作或擅自延长尾段。 Use global `instructions` only for appearance and preservation rules; each segment instruction covers that segment's actions. A segment may override the shared `reference_assets` with its own complete ordered list. `start_from_segment` names an earlier segment and replaces exactly one `start_state` reference with its accepted real tail; the dependent segment waits for that candidate to be reviewed and accepted. Review sequence continuity, including hands, garment opening, camera and scene, before allowing the dependency.
4. Keep planning, edits and input checks in the local task workspace; no server draft is needed while editing. Do not create valid probe jobs to investigate an invalid payload. When the user explicitly submits the plan, call `create_video_job` once with `generation_mode: "six_references"`, then immediately persist the returned `job_id` with the plan and asset IDs outside this package. Inspect the returned mode, plan and reference order, then prepare that same ID. The existing create→prepare sequence remains supported. A create response lost to a timeout is unknown: stop automatic POSTs, recover with the lifecycle list and `get_job`, and explain ambiguity if the task cannot be identified uniquely. There is no create-idempotency or remote draft-edit API in this release.
   Read `get_job`; show snapshots, hashes, semantic windows, segment prompts, ready/dependent status, current quote and any unsettled costs. Obtain budget consent within the user's actual authorized scope. Use `render_video_job` with `max_coins` and the `review_token` from the review actually shown. If inputs or quote change, show the updated review; do not fetch a fresh token merely to bypass a conflict. `max_coins` is not a confirmed upstream price ceiling when cost is unpriced. The server enforces at most three RunningHub video requests across the account; call render for a ready wave, then poll the same job ID. Do not make repeated submissions on timeout or unknown receipt.
5. `get_job` exposes `ready_segment_indices`, `candidate_review_token`, candidate hashes/tail URLs and `candidate_timing` per segment. The timing status `compatible|incompatible|unknown`, reason, measured/kept/delivery durations, allowed kept range and ratio are a free deterministic check, not visual acceptance. If timing blocks review, inspect its safe reason and current media/window before another decision; do not repeat the same invalid review, automatically trim or pay for a retry. Play each candidate video and inspect the full action, identities, product, scene, sleeve/trim details, joins and audio. A frame or waveform alone is not proof of video quality. `review_video_segments` sends exact `{segment_index,candidate_sha256,action: accept|retry,reason?,trim_start?}` decisions with the current `candidate_review_token`. An accepted candidate may use a reviewed nonnegative `trim_start` to remove a repeated opening, but check the actual kept action and duration; retry cannot include it. A terminal failed segment reports `candidate_sha256: "failed"`; retry it only with a specific reason and authorization. A retry is a new paid attempt; accepted segments are reused. If an existing upstream submission has an unknown outcome and the job is in `attention`, call `reconcile_video_job` to check the recorded receipt without submitting fresh generation. After all candidates are accepted, call `assemble_video_job` with the current candidate token. Play the complete assembled output at normal speed, verify actual dimensions and decode, then report any unresolved defects and costs.

Existing jobs retain their recorded provider route; do not convert them or assume an old approval covers new paid work. Keep historical paid costs separate from new attempts and do not treat old project budget balances as this user's authorization.

Additional paid retries need separate explicit authorization. Do not auto-accept known defects, skip requested user review or change serial dependencies for speed. Every final delivery includes a complete-video entry and an entry for every segment; state official assembly failures and label any authorized local fallback separately. `completed` and candidate acceptance do not establish user satisfaction. Save a template only after explicit satisfaction plus a request to save, using the exact delivered output hash and supported tools.

For capacity, cancellation and explicit closure, read `jobs-and-assets`. Discover lifecycle support on the live `video.replicate` capability or remote tools; a bundled stdio tool list alone does not prove server support. Use `get_account_usage` and `list_video_jobs` after structural 429; do not repeat create or switch keys. Drafts and active tasks each have a default limit of 10, separate from the provider's three concurrent requests. Only cancel a user-selected or explicitly authorized disposable never-started draft. A user who explicitly abandons a specific stopped review/attention task may close it if the current summary says `can_close:true`, using `close_video_job` with that task's revision. Never choose or batch-close tasks to bypass quota. Closure releases active capacity, retains media and audit records, and makes the task terminal; do not continue it. Unknown receipts or unfinished work remain recoverable. Eligible never-started drafts expire 24 hours after creation as `cancelled` with `draft_expired`; reading or polling does not extend the deadline. Protected drafts have a blocked reason. Starting fresh requires a new explicit submission and fresh input/quote review as applicable.
